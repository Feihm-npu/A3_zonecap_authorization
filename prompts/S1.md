# S1

Goal: turn the project into falsifiable claims and a plan that can refute them cheaply, on infrastructure that already runs.

## Read
- `AGENTS.md`; everything describing the project (README, notes, code, data).
- If `research/PROBLEM.md` exists, this is a return: read `STATE.md` `note` and `research/REVIEW.md` for the human's comments. Revise; do not restart.

## 1. Problem and gap → `research/PROBLEM.md`
- Gap in the form: existing methods X achieve Y but fail at Z because W; we hypothesize V addresses W.
- Closest prior work via web search: 3–5 entries, each with what it does and the delta.
- A gap is real only if the delta is explicit, someone would care, and it is not a trivial combination of existing work. If not real, say so in PROPOSAL and exit to `S1_AWAIT` anyway.

## 2. Claims → `research/CLAIMS.md`
- 2–5 claims, 1–2 tagged `core` (if they fail, the project fails). All tagged `[S1]`.
- Each: statement, observation if true, observation if false, alternative explanations for the "true" observation.

## 3. Plan → `research/PLAN.md`
- Per claim: main comparison, one ablation per alternative explanation, the strongest fair baseline, a sanity check.
- Fix metrics, splits, seed count, and evaluation protocol now.
- Order rows so the cheapest experiment able to refute a core claim runs first.
- Estimate GPU-hours per experiment; flag any beyond the default compute.

## 4. Infrastructure
- Pipeline runs end to end at small scale: data → train → eval → `results/<run_id>/`.
- Baselines reproduce their reported numbers, or NOTEBOOK records why not.
- Evaluation code is frozen after this step.

## Exit
Write `research/PROPOSAL.md` in Chinese (template below), claims verbatim in English. Set `STATE.md`: `state: S1_AWAIT`, `awaiting: human`, `read: [research/PROPOSAL.md]`, `options: [S2_RUN, S1]`. Append log line. Commit.
