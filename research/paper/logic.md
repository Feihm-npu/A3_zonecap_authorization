## Paragraph map

### Abstract

1. **Context:** delegated cross-zone commands need an authorization object whose scope includes physical consequence.
2. **Gap:** capability narrowing and runtime editing remain separate guarantees.
3. **Approach:** ZoneCap connects table compilation, field-wise attenuation, request-abstracted emissions, and plant traces.
4. **Result:** report the decisive C1, C6, and C7 numbers.
5. **Boundary:** delayed revocation refutes C4 and target-hardware performance remains unmeasured.

### Introduction

1. **Context:** industrial agents and software principals can issue actuation across zone boundaries.
2. **Prior capability:** CPS capability systems minimize digital privilege but do not prove physical reachable-set refinement.
3. **Prior enforcement/modeling:** physics-aware access control and edit automata constrain commands but do not connect delegation syntax to the induced physical behavior; IEC tooling models risk/topology rather than delegatable actuation scope.
4. **Gap/insight:** the missing link is an emission refinement relation derived from positive conjunctive token syntax plus parent-realizable effects.
5. **Contribution:** list C1, C6, and C7 at their accepted scope, then preview C4/C5 boundaries.

### Related work

1. **CPS capabilities and agent authorization:** Dodson/CHERI Macaroons, SINT, ZTPM, and DARC; distinguish physical reachable-set refinement and source-grounded compiler scope.
2. **Physics-aware policy and runtime enforcement:** CPAC, Smart I/O, Lanotte/Roop, and Baird; distinguish authorization/delegation semantics from enforcer mechanisms.
3. **IEC 62443 modeling:** risk-assessment automation and zone/conduit DSLs; distinguish runtime capability generation from standard modeling/conformance.

### Method and theorem

1. **Formulation:** define capability fields and physical semantics.
2. **Compiler:** validate topology and intersect positive authority dimensions.
3. **Delegation:** check field-wise subset/prefix conditions without plant reachability.
4. **Runtime semantics:** define all five effects, physical outputs, timeout, and fail-closed behavior.
5. **Refinement:** prove compiler refinement, emission refinement, then trace/reachable-set inclusion.
6. **Boundary:** list the six obligations and registered failure cases.

### Results

1. **C1:** proof closure and exact 1D audit.
2. **C1 alternatives:** unsafe mutants, MIMO/history seeds, effect premise removal/restoration, common-subset baseline, sanity.
3. **C6:** complete held-out corpus and oracle agreement.
4. **C6 alternatives:** generated-versus-handwritten mutants, provenance probes, paths/depth/widening, baseline expressiveness, sanity.
5. **C7:** five-effect one-request and composed traces.
6. **C7 alternatives:** deny-only service loss, exhaustive sequence coverage, baseline mapping, fail-closed sanity.

### Discussion and conclusion

1. **Meaning:** physical monotonicity is a refinement-contract result, not a property of capability syntax alone.
2. **Relation:** ZoneCap complements capability systems and runtime enforcers instead of replacing their mechanisms.
3. **Negative boundary:** revocation issuance must be connected to execution by freshness or an atomic delivery contract.
4. **Limitations:** shared source encoding, synthetic overlay, bounded effect semantics, trusted context/model, missing Jetson/OpenPLC measurements.
5. **Close:** state what is reusable now and what remains unclaimed.

## Claim-language guardrails

- Use `establish` or `prove` only for the conditional C1 theorem under all six named obligations.
- Use `matched` or `agreed` only for the complete frozen C6 corpus; never write `IEC 62443 compliant`, `generalizes to IEC architectures`, or `certified`.
- Use `preserved in the registered bounded semantics` for C7; never imply fixed-tick or distributed execution.
- Use `refuted` for original C4 and `remained clean after delivery` only for the narrower observation.
- Use `not measured on the approved testbed` for C5; never reuse exp-26 latency as performance evidence.
- Avoid `first`, `novel`, `comprehensive`, `always`, and `guarantees` unless immediately bounded by the theorem premises.
